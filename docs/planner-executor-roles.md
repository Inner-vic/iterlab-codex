# Planner–Executor 与 Generator–Critic

> 实现/设计参考，非端到端验收承诺。当前项目按[学习参考原型](preservation-status.md)留存；真实范围以[最新验收](lpai-core-acceptance-20261112.md)为准。

上层使用 Planner–Executor。Planner 负责目标、假设、方案选择与结果决策；Executor 实施确切方案并返回真实证据。Planner 内层使用 Generator–Critic：生成/改进与独立质疑分开，不属于随机分组 A/B Test。

模型与连接界面只保留 `Codex CLI` / `EPT Codex CLI`、规划模型和执行模型。Planner、Generator和Critic共享规划模型，Executor使用执行模型。代码中的渠道默认建议不是模型可用性或额度保证，不应将历史模型名称当作当前固定推荐。实际使用前检查本连接的`model/list`，不可用时阻断，不静默替换。EPT profile、能力范围和旧模式模型不再作为界面选项；旧文件字段保留兼容，不改官方CLI或凭据。打开页面不会改写旧配置，用户保存后合并为两模型配置，应用于所有会话的后续轮次；当前轮次及旧路由/审议历史不改。

Critic的独立性来自单独轮次、反证视角和可查证的评审来源，而非必须更换模型。审议先核对原始证据、固定协议和关键假设，再判断作者论证；关注竞争解释、反例、公平比较、泄漏与执行可行性。每项实质质疑给依据或未知、可推翻判断的观察和最小补证，不机械要求新实验。已解决的问题应记录关闭。Critic必须保存当前轮次自己的评审，不能复用Planner自评作批准，也不能改方案或启动训练。同线程仍可见共同历史，当前不是独立上下文盲审，也不保证消除共同偏差；真实质量收益未做对照验收。

当前表单不展示推理强度，保存时使用模型默认（effort=null）；后端历史字段保留兼容。渠道切换刷新渠道默认模型，保留原profile与能力范围；不自动转换现有会话归属或重置研究授权。

`lab/roles.py` 保存逐投递角色、具体模型、交接方案与摘要、来源评审/反馈以及原生工具合同前缀。`lab/kernel.py` 在原生 `turn/start` 设置模型和沙箱，持久交接在当前原生轮次结束后进入同一业务投递队列。App Server 继续拥有唯一的推理、工具、审批及上下文循环；程序不另起 LLM 决策器。

Executor 交接分为 `prepare` 和 `execute`。前者允许先实现与离线检查、回收审议材料，拒绝受控运行、平台准备/提交和资源操作；后者仍须同一方案的 Critic 批准与有效研究资源授权。正式执行发起模型轮次前再次核验授权。两种阶段都不允许 Executor 新建方案或自批评审，反馈必须引用真实文件。预算、暂停、未知投递与原平台审批保持原语义。

旧原生线程可能保留旧工具定义。此时可通过原有 `research_record` 的严格保留标题业务信封完成相同交接：标题 `__iterlab_role_handoff_v1__`，kind=decision，status=proposed，evidence=[]，content 为 `iterlab-role-handoff/v1` JSON。仅严格信封进入同一门禁，不解析普通正文为控制指令，不为业务交接新增研究节点。无需换线程或重新发送未知请求。

有待交接角色时，原有自主续接队列优先处理该事件，避免额外唤醒通用 Planner。后续人类输入使旧待交接失效；旧未知投递保留，不自动重试。角色合同前缀固定到每次投递，并作为方法信封保留，不在聊天里冒充另一条用户消息。

本工程保持独立：不在运行时导入 SDM 协调器，不连接其数据库或读取其凭据。所有实际研究与资源权限仍由本工程既有授权实现核验。

回归入口：`scripts/run-quiet.ps1` 包装真实 Python，执行 `-B -m unittest discover -s tests -q`。`tests/test_roles.py` 包含模型目录、同一方案审议、阶段限制、授权撤回、旧线程兼容、投递去重、消息投影与续接优先级回归。

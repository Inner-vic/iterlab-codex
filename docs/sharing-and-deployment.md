# 源码分享与本机部署

本项目按学习参考原型分享应用源码，不按可直接使用的产品交付；当前结论见[参考范围](preservation-status.md)。如需调试，每人运行自己的服务和数据目录。开发者已有的项目、会话、实验、云任务身份和登录状态不应随源码迁移。

首次启动已加入依赖检查和缺失项安装，详见[安装说明](dependency-setup.md)。`scripts/setup.ps1 -CheckOnly` 可先只读核对，安装报告和依赖保留在各自 `.runtime`。仍需使用自己的官方登录；EPT 官方分发源尚待确认，当前不会自动安装未知 EPT 软件包。

## 1. 共享目录约定

- 日常启动入口改为根目录 `app.cmd`，自动识别 Python，不写死用户名和安装路径。原中文入口已重命名。
- 个人启动入口和旧文档备份留在本机忽略目录，不作为同事启动入口。
- `.data`、`.evidence`、`.runtime`、历史验收资料及专用实网脚本保留原位置，避免破坏历史证据路径，通过 `.gitignore` 排除。
- 根目录、脚本和文档采用共享白名单，通用代码、离线测试、图谱构建源、打包资源及许可上传。新增文件需按目录规则审阅后纳入。
- SDM 导入清单采用逻辑来源说明及文件摘要，不带开发者绝对路径。旧项目仍使用自己的历史方法快照。
- 历史 `nofit_loop_acceptance.py` 及其专属测试属于个人实网验收，不纳入便携源码；通用运行桥接和其离线测试保留。

## 2. 哪些内容不能上传

| 范围 | 含义 |
|---|---|
| `.data/` | SQLite、用户配置、项目文件、聊天、方案、实验、产物、方法快照、任务身份及服务状态 |
| `.evidence/`、`docs/acceptance/` | 验收数据库副本、收据、日志、云任务信息和截图 |
| `.local/`、`docs/progress.md`、非白名单文档/脚本 | 本机路径、个人排障过程、操作决策和实网驱动 |
| `.runtime/`、`.venv/`、`node_modules/`、缓存 | 各自重新安装的依赖，不复制虚拟环境 |
| `.env`、密钥、凭据文件、数据库、训练权重 | 各自登录、保存在仓库外或已忽略目录 |

不要把官方 Codex/EPT、LPAI、GitLab、SSH 的用户目录配置复制进仓库。新的数据集、截图、训练输出应放入 `.data`、`.evidence` 或独立于源码的存储位置。

静态图谱 bundle、CSS、图标、`frontend/exploration-map/package-lock.json` 和第三方许可需要提交。它们是运行资源，不应当作缓存排除。

## 3. 检查与导出

在本项目目录运行 `scripts/source_bundle.py`，使用 README 中的 `run-quiet.ps1` 包装方式。

同时运行 `scripts/check_docs.py`，检查Markdown本地链接指向的文件是否真正随源码分发，而不只是开发者磁盘上存在。文档导航见[文档目录](README.md)，本次整理结果见[仓库复核](repository-audit.md)。

默认只生成本机报告 `.evidence/source-bundle/latest.json`。程序使用临时空 Git 仓库评估当前 `.gitignore`，检查必需运行文件和常见嵌入凭据模式，不启动服务、不导入用户数据库、不调用模型、不发网络请求、不修改实际 Git 索引。

传入 `--output .evidence/distribution/iterlab-source.zip` 可生成源码包。包内路径是项目根相对路径，解压后直接运行 `app.cmd`。同名包已存在时拒绝覆盖；源码在打包途中变化则报错，不应分发未完成包。忽略规则与常见凭据扫描不是完整安全审计，提交前仍需检查差异，特别是新增配置与企业资料。

源码包使用独立空索引枚举，避免把真实仓库中曾被跟踪、现在已忽略的本机文件打进去。直接上传 GitLab 仍需检查真实索引。

## 4. 首次上传 GitLab

本项目已使用独立的GitLab源码仓库；同事可直接阅读，需运行页面时再按README尝试app.cmd。启动成功不代表模型、平台或研究闭环已可用。后续源码更新仍须审查暂存区和测试结果，不能把本机数据目录提交。以下命令仅供首次建立其他独立仓库参考，不要在包含其他个人项目的父目录执行 `git add .`。

首次建库的参考步骤：

```powershell
git init -b main
git add .
git status --short
git diff --cached --stat
git diff --cached
# 确认暂存区无本机记录/凭据后，再由你执行提交和推送。
```

如果已有仓库，`.gitignore` 不会移除已跟踪的文件。先用下面命令列出“已跟踪但按当前规则应忽略”的文件：

```powershell
git ls-files -ci --exclude-standard
```

逐项确认后仅从索引取消跟踪，保留磁盘原件，不要运行批量删除命令。已上传到 Git 历史的凭据不会因新增 `.gitignore` 消失，需撤销凭据并另行处理历史。

## 5. 可选本机调试

1. 安装 Python 3.11+ 和 Codex CLI 或 EPT Codex CLI，完成自己的官方登录。
2. 克隆源码到本机可写目录，双击 `app.cmd`，访问 `http://127.0.0.1:8781/`。
3. 首次运行生成自己的 `.data`；在界面选择模型渠道，需要公司平台时再检测自己的官方登录、权限和网络，安装本机 SDK 环境。
4. LPAI 空间/组件、SSH 密钥和项目仓库按各自实际任务绑定。不能继承开发者任务 UID 或假定已有 GPU/结果卷。
5. 更新源码时保留 `.data`，确认本地执行空闲后正常停止服务、更新并重启。

本地备份使用标准压缩快照，核验和恢复入口见[存储管理](storage-management.md)。数据库/配置备份不等于工作区文件备份；交接源码也不应包含开发者的研究数据或个人登录资料。

关闭启动窗口或浏览器不等于停止后台服务。电脑关闭或休眠期间，本机监控和 Codex 接续无法工作。当前是本机单用户应用，尚未提供安装器、自动升级、Windows 服务注册或多人集中部署能力。

## 6. 保持与验证范围

本次不移动、删除或重排已有项目、会话、实验及产物，不改变平台绑定，也不触发新的训练或模型会话。源码整理和打包验证不能代替新机器实测；同事首次安装的 CLI、SDK 和公司权限仍需在其机器核对。

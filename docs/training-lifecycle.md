# 训练提交与持续迭代：运行约定

> 实现/设计参考，非端到端验收承诺。当前项目按[学习参考原型](preservation-status.md)留存；真实范围以[最新验收](lpai-core-acceptance-20261112.md)为准。

如何判定能力通过，统一见[核心验收标准](core-acceptance.md)：单轮自动提交/监控/回收与结果驱动的连续闭环分别验收，不能用工程重试或人工代推进代替有效轮次。

## 当前主线

首次确认研究目标、运行位置、GPU 上限和必要资源边界后，Codex 在原生单一执行循环中准备实验。IterLab 负责核对确切方案、冻结输入和平台身份、提交、持久后台监控、产物回收，再投递到原会话分析。假设解释、实验选择与上层方案修订由 Codex 根据证据判断，不固定成“负结果就换模型”。

## 训练前检查

- 开发空间 ready、SSH 成功只是连接就绪。拟合请求还需核对原空间身份、Python、可写目录，以及已批准设备上的最小 CUDA 内存分配。
- CUDA 检查为固定程序：复用当前设备掩码，不搜索其他更空闲的 GPU，不增卡；只创建必要 CUDA 上下文、分配并释放4字节，不读取数据、不训练、不安装依赖。记录当时可用/总显存。CUDA 上下文本身也需要少量驱动管理显存。
- 此检查位于登记正式训练尝试之前；失败不创建 research_run、不上传训练输入、不扣任务次数，并记录 environment_blocked。不能因失败切到本地。诊断请求可以继续用于定位环境，不必先通过拟合检查。
- CPU 空间不要求 CUDA 或 nvidia-smi，远端监督器也不因缺少 GPU 工具拒绝 CPU 执行。
- 最小分配通过不保证完整模型显存足够、训练代码正确或研究目标达成。具体框架/模型依赖和预期显存仍需方案准备检查。
- 组件库在 GPU 分配后、冻结训练入口执行前运行同一固定预检。实际角色规格决定各容器的 GPU 数量，源码和数量随执行工作包冻结；旧工作包不能热改。失败记录 gpu_environment_failed，训练命令不会执行。此时平台已经提交，所以仍计一次任务；预检耗时计入完整入口时限。证明合并到 iterlab-runtime.json，避免额外文件挤占小型产物回收范围。真实 GPU 前向/反向仍须训练产物支持，不能用最小分配替代。

## 任务上限，拟合事实与资源边界

普通界面只设置累计任务提交上限和单次时限；GPU 数量仍遵守最初批准的上限。未给预算建议的新方案默认留出100次额外任务空间，可明确调整，技术最大累计1000次。模型建议了具体任务范围时按其方案展示，用户确认后生效，不在后台擅自延长。

普通新方案的兼容 max_fits 与 max_runs 相同，不再另设更小的拟合额度。运行目的、实际拟合事实保留在后台，便于审计、研究比较和异常定位；这不是限制模型内部训练轮数的配额。一项已提交任务内部仍受单次执行时限和方案/资源边界约束，不能靠改用途或套循环规避时限。

旧审核、旧累计和原始消息不改写。旧显式零拟合/特殊拟合边界保留；正式任务扩容入口未传旧 add_fits 时，将普通非零拟合额度同步到任务上限，追加不可变预算修订，不重写 grant。显式零拟合或方案声明的零拟合诊断仍不扩展计算权限。关闭轮次和人工暂停不能被扩容重新启动。

普通对话和进度面板不再反复展示“已用运行/拟合”的账本分数。后台仍核对累计，只有实际到达边界、需要延长或调整资源时说明原因与选项。自动续额仅在用户预先确认的累计硬上限内进行；不会扩大 GPU、修改运行位置或重置历史。

## 失败、修复与研究判断

旧轮次因预算或无进展结束后，新的用户输入可以提出新的执行范围。程序把新候选关联到该输入、原方案和最新评审；允许方案讨论、Executor 的离线 prepare 和 Critic 审议，不复活旧 grant。新 GPU 范围只有在正式新范围审核后才产生执行授权。新的停止、暂停、归档、未知请求或执行阶段交接仍会拦截，旧收束记录、累计和证据不改写。

提交/环境/输入/训练执行异常先按工程问题处理。同一实验修复和重跑沿主线关联；结果未知先查原身份，不新建替代任务。不把环境失败当成模型能力的负结果。

工程主线保存在同一实验的运行详情，不把每次失败、修复和重跑展开成研究图节点。程序取证只保存诊断索引、证据文件和事件，不自动新建科学研究记录；同方案失败后的重跑必须复用原 trial。既有记录不删除、不改编号：仅依靠同会话的明确失败前序和可靠方案分支归属，在展示时收拢历史重试实验卡；没有明确关联不按标题或时间猜测。详情保留每次任务 UID、原实验/方案、修复及验证、诊断、产物报告。

两种研究图视图均隐藏程序诊断与明确重试副卡，原始记录列表和直接详情仍可查。折叠边只标运行背景，不把历史顺序重新认证为科学因果。模型效果下降、训练发散等研究结果不因 failed 状态被自动隐藏；必要的科学分析可明确引用运行诊断。平台成功但归档尚未核验时，收拢后的实验也不能显示为证据已就绪。

下一步应说明观察、受影响假设、仍需区分的解释和最小必要改动。重复同一错误、未变配置、没有新增证据时不得靠放宽次数盲目重投。Critic 审查修改依据和比较公平性；训练完成先核对本地产物，再做结果解释。没有可核验指标时不能宣称涨分、达标或模型无效。

## 回收失败与晚到证据

本地证据自动回收最多共三次，注册尝试前的失败也计入；同一原身份的累计和退避在重启后保留。耗尽后保留原收据、全部清单和缺口，交由既有只读缺口评审处理，不无限生成归档或重训补证。已损坏归档仍不自动覆盖。

训练终态与结果到达是两个事实。晚到的本地可分析归档、组件产物归档或终态取证可以打开一次新的研究分析进展窗口；它本身不授权计算、不解除用户暂停/未知请求、不认证模型有效性。云端新归档的稳定证据摘要只覆盖实际文件字节与确切来源；相同字节另一次复制、改路径、改时钟或报告文字不算新进展。原生Codex仍在原会话作科学判断，不新增独立LLM循环。

## 尚待真实验证

当前最小 CUDA 检查已用隔离故障回归验证，并未新增实网 GPU 训练。仍需可用 GPU 空间/组件上的真实基线、模型自主选择的后继实验、产物回收及原会话接续；涉及服务重启、断线和负结果的组合需单独记录人工介入。工程测试不能替代研究判断质量或完整显存需求验证。

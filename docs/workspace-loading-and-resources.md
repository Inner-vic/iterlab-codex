# 页面加载、运行与账号资源

## 加载方式和边界

会话先加载最近一页，向上查看再读取旧页；已加载页保留，切换会话有请求代际保护。这是分页加载，不是无限规模的双向 DOM 淘汰。稳定标识复用消息节点，流式文本按动画帧更新；不能仅凭请求字节下降宣称耗时已改善。

脉络、实验、文件和运行展示各自持久对象。图谱折叠工程尝试不删除证据。文件预览及放大视图使用同一来源，路径限制在项目内；大文件仍占传输和浏览器内存，不能承诺无限预览零成本。

「运行」合并位置配置与本会话运行观察。只有开发空间需要 SSH。本地和组件库无需填写；地址、身份和诊断留在详情，不另造全平台管理中心。

## 账号资源目录

集群、队列、套餐、镜像和输入资产按当前登录账号及工作空间读取。目录短时缓存（资源约60秒），不固定某人的三个队列，也不把全局规则目录当作可申请资源。读取失败明确失败，不回填另一账号缓存。

列表展示平台实际返回的名称、GPU 类型、套餐规模及可取得余量。公共/专属只作辅助。卡数、台数、套餐数量按官方单位解释，不能把8卡起配套餐当作可申请1卡。

## 推荐、确认与切换

1. Codex 根据任务、数据、代码、多卡支持和成本，推荐位置、GPU 类型/数量、镜像、输入及结果存储。推荐须有可用性证据，不是有空闲就扩大训练。
2. 程序读取账号资源和资产，验证配方，随方案固定确切配置。初次资源授权及 GPU 上限由用户确认。
3. 确认后按冻结配置创建组件并提交；高级选项可复用组件，普通用户不必填 UID。
4. 后续在运行配置/方案选择目标资源，重新校验硬件兼容、镜像、分布式入口和授权。正在运行的任务不变；切换影响后续任务，不能改写原身份。
5. 未增加 GPU 也不等于任意变更兼容；扩大范围或卡数重新确认，不能因套餐空闲从单卡静默变8卡。

配置建议、账号可见、平台接受、实际调度和训练有效是不同事实。余量不可靠时保留未知，推荐不保证立即获得资源。详见[平台接入](company-integration.md)。

## 维护与验证

模型目录按渠道读取并短时缓存，详见[模型连接](model-connection-simplification.md)。后台任务查询不消耗模型 Token，结果分析会使用模型。服务关闭时没有轮询，缓存不能显示为实时事实。

加载应分别验证首屏、分页、滚动位置、会话切换、流式输出和长图谱，不能以静态截图替代性能证据。离线回归和真实云验收范围见[核心交接](core-handover.md)。

# 模型与连接

> 实现/设计参考，非端到端验收承诺。当前项目按[学习参考原型](preservation-status.md)留存；真实范围以[最新验收](lpai-core-acceptance-20261112.md)为准。

## 用户需要配置什么

选择 `Codex CLI` 或 `EPT Codex CLI`、规划模型及执行模型。复用该 CLI 本机已有登录，IterLab 不复制登录凭据。没有登录或额度不足时明确提示，不静默切换渠道、账号或计费来源。

Planner、Generator 和 Critic 共用规划模型，Executor 用执行模型。角色职责来自独立轮次和工具门禁，不要求为 Critic 再配第三个模型；它也不是独立上下文盲审。详见[角色职责](planner-executor-roles.md)。

EPT profile、能力范围和旧模式模型不是日常表单项，兼容字段仍可保留在旧配置。打开弹窗不改配置，保存后作用于所有会话的后续轮次；已在运行的轮次和旧证据保持原模型。

## 模型列表与推理强度

打开配置时自动读取当前渠道完整的 `model/list`（包括可见隐藏项），不是只显示当前选中的两个私有模型。目录使用独立只读进程及约60秒缓存，避免查询干扰研究线程；短时缓存不是永久固定模型清单。

当前所选模型不再可用时显示状态，保存/执行前校验，不能用显示名称冒充实际模型 ID。系统提供渠道默认建议，但实际以当前目录为准；公司动态上下架后不应继续信任过期硬编码列表。

当前表单不提供推理强度选项，保存两模型配置时使用模型默认（effort=null）。后端保留历史配置兼容能力，不代表界面仍有强度下拉框。默认也不证明模型内部一定采用某种固定推理量。

## 读取失败

先核对 CLI 安装、登录、模型目录请求、进程退出和网络。模型列表是只读请求，可隔离恢复查询；研究 turn/start 返回不明确则必须核对原请求，不能借读取列表重启并重发研究消息。

失败信息保留安全分类，不显示凭据；读取失败不覆盖已经保存的配置。模型连接成功、可以列模型与完成真实研究是不同层级，不能只用下拉框验收模型切换。

# 本地数据库：无需单独部署服务

IterLab使用Python自带的SQLite。拉取源码后运行`app.cmd`，程序会在自己的`.data/`中自动创建数据库、数据表、索引和缺省状态；不需要安装数据库服务器、导入开发者的数据库、创建账号或填写连接字符串。

| 项目 | 自动默认值 |
| --- | --- |
| 数据目录 | 项目根目录下`.data` |
| 数据库文件 | `.data/workbench.sqlite3` |
| 初始化/升级 | `Store`及功能模块幂等建表，`schema_versions`记录已应用版本 |
| 写入日志 | SQLite WAL；`-wal`和`-shm`由SQLite维护，运行时不要单独删除 |
| 关联校验 | 每次连接启用外键校验 |
| 新用户数据 | 空项目、空会话、空研究记录；不植入作者测试数据或GPU授权 |
| 模型连接 | 检测本机CLI，模型默认值由官方连接核对；不复制作者模型账号或余额 |
| 平台连接 | 初始不启用；点击连接后自动检查、复用本人登录，缺项才引导 |

代码中的初始化和迁移就是数据库配置的正式来源，随源码一起交付。不要把`.data/settings.json`、已有SQLite或作者平台绑定作为默认配置上传。平台namespace、GitLab目标可在界面高级选项按账号调整，默认值不代表授予访问权限。

只在需要把数据存放到其他磁盘时设置`ITERLAB_CODEX_DATA`，之后保持同一路径；日常使用不需要设置。移动前停止本机服务并备份，不能只复制运行中的主SQLite文件而遗漏WAL。更新源码不会清空已有数据。备份与新目录恢复见[存储管理](storage-management.md)。

公司登录、SDK Token、SSH密钥仍由本人完成首次授权；SQLite开箱即用不表示企业认证可以免除。当前部署是每人本机一份，服务绑定`127.0.0.1:8781`，不是多用户共享数据库服务。

# 研究方案发布规则

方案编号用于定位研究决策，运行次数单独记录。发布指保存一份完整、可评审的方案快照；采纳和执行授权由原有门禁分别判断。

| 发生了什么 | 记录方式 | 示例 |
| --- | --- | --- |
| 修复依赖、路径、权限、提交配置，随后用相同研究设置重跑 | 原实验下追加尝试，保留失败、修复、任务 UID 与产物 | 方案 1.1 保持不变 |
| 执行方案中已约定的调参、种子复核或消融 | 在原方案下记录实验和比较结果 | 方案 1.1 保持不变 |
| 证据要求修订同一路径的实验设计，例如增加能区分两种解释的对照 | 发布第三段修订，明确继承和改动内容 | 1.1 → 1.1.0 → 1.1.1 |
| 评审收束当前探索路径，证据支持同一总体路线内的另一方向 | 发布同系列下一路径，引用原方案与结束该路径的评审 | 1.1.1 → 1.2 |
| 更换总体技术路线或核心研究假设 | 开启下游新系列，关联促成改向的评审 | 1.2 → 2.0 |

## Agent 如何判断

启用角色编排时，Planner 或 Generator 保存的后继方案先成为无编号候选。Critic 复用独立评审轮次，核对是否需要发版、级别是否合适，以及原证据是否支持该改动。工程修复应归回原实验。级别需要调整时退回并说明理由，由作者另存候选。补证和退回均不占号。

Critic 批准后，宿主复核同一候选的摘要、冻结证据、前轮及评审关系，在保存交接时正式分配编号。随后由 Planner 通过原授权流程采纳，候选阶段不能批准执行。初版仍走首次审核，显式人工分支沿用人工干预入口。

先读取当前方案、相关实验结果及冻结的评价协议。若只恢复原实验的可执行性，沿原实验记录尝试。若实际改变了科学检验，说明观察、竞争解释、保留项、改动及能区分什么，再判断是原路径修订、路径切换还是总体改向。保留原对照及评价口径。证据不足时可先记讨论或诊断，待形成完整提案后再保存。

Codex 通过 `research_record` 声明 `incremental`、`route` 或 `major`，并填写前轮、评审、修订理由及促成记录。宿主校验引用和门禁，在保存事务中分配版本并保留正文及证据摘要。编号表示研究关系，不授予执行权限。用户目标、评价或资源超出已确认范围时仍走现有授权流程。历史 UCI 编号保持原样。

# LPAI 与 GitLab 接入

> 实现/设计参考，非端到端验收承诺。当前项目按[学习参考原型](preservation-status.md)留存；真实范围以[最新验收](lpai-core-acceptance-20261112.md)为准。

本文说明当前实现。连接使用各自电脑上官方工具的登录，不继承开发者账号。CLI 已安装、账号可访问、资源可用和训练成功是不同的检查。交付结论见[核心交接](core-handover.md)。

## 连接和运行位置

设置尽量识别本机已有登录，地址及诊断放在高级选项。连接是全局配置；仓库、主开发空间、实验与任务身份由项目或运行保存。换账号后必须重新读取可见资源，不能沿用上一账号的列表或凭据。

| 执行方式 | 前提和实际执行 |
| --- | --- |
| 本地 | 验证解释器和实际 CPU/GPU；不要求开发空间 SSH。 |
| LPAI 开发空间 | 官方网页创建空间，IterLab 发现并绑定项目主空间；验证该空间 SSH 后传输文件、运行远端监督器。 |
| LPAI 组件库 | 按方案冻结的资源、镜像、输入和输出配置创建组件并提交任务；高级选项可复用组件。无需开发空间 SSH。 |

方案应解释位置选择。选定云端位置后失败只能修复、等待或明确调整方案，不能静默本地代跑。绑定空间不等于 SSH 验证通过，启动空间不等于训练运行。

## 官方接口与审批

- `lpai-agent` 承担官方查询及开发空间启动/停止；组件库训练使用官方训练 SDK 的 `Task.submit`。具体参数由代码适配，不要求研究模型每轮探索命令。
- 研究授权、GPU 上限和平台强制审批分别校验。IterLab 确认不能绕过平台 `pending_approval`；审批收件账号和登录需按官方配置核对。
- 当前不提供完整的原生开发空间创建功能。可跳转官方网页手动创建再发现、绑定；开发助手通过客户端操作网页不是产品自有能力。
- 普通已授权操作不逐条要求点击；首次或增加 GPU 数量、扩大研究范围和平台强制确认仍保留边界。

## 开发空间 SSH

项目「运行」可发现官方端点，匹配本机已有密钥并只读验证；不匹配时可手动指定私钥路径。保存该空间配置，私钥不复制到仓库或发送模型。其他电脑使用自己的密钥及平台授权。

提交前重验绑定空间、平台状态、SSH、Python 和所需 GPU/CUDA。CPU 空间无需强制 `nvidia-smi`；GPU 最小 CUDA 分配失败则拦截，不扣尚未提交的训练次数。404 标为平台未找到，可解绑/换绑，旧实验保留实际身份。

冻结输入经 SSH 上传，远端任务身份持久保存。浏览器断开不等于训练停止；回收以声明的小型结果为主，大权重不是无条件下载。限制与生命周期见[训练说明](training-lifecycle.md)。

## 组件库提交和恢复

资源与镜像来自当前账号，不能用全局目录冒充可申请资源。方案固定提交配置，确认后创建组件、保存 UID，再提交任务。队列余量只是快照，不保证调度时间；详见[资源说明](workspace-loading-and-resources.md)。

原生 `company_context` 提供与实际编译器一致的 `component_recipe_contract`，说明必需字段、账号身份、镜像和挂载的结构及读取来源，不提供个人账号默认值。组件 recipe 与 `lpai_prepare` 的运行/产物合同分开，不能把展示名称、规格读回或 `output_contract` 混进 recipe。

`research_write` 保存 Python/JSON 后在同一回执返回非执行的语法检查；组件配置额外返回结构错误。坏文件仍保留供修复，不自动改配置或执行代码。已有检查通过时无需重复开终端做同一语法检查；依赖、目标Python版本、CUDA和算法正确性仍须另外验证。结构错误也会在审核预览启动 SDK 之前拦截，冻结文件、账号/资源实查及提交门禁保持。

创建或提交不明确时保留原请求。组件创建可按原名称和已批准的完整配置只读核对；成功后绑定原 UID，准备恢复事件只投递一次。不能重复创建或重放未知任务。暂停、账号/连接变化、配置冲突和未核对的任务继续阻止推进。

后台只监控本会话提交或明确绑定的任务，不复制全平台管理。轮询不调用模型；终态先回收产物并核对身份，再按授权向原会话接续。缺产物只报告工程失败或证据缺口，不编造指标。

训练 Pod 创建前也可能失败。诊断保留官方流程阶段及可取得说明；数据准备失败只定位阶段，没有日志不能断言具体根因。停止 Codex 不自动停止云任务，平台停止需要明确操作意图。

## GitLab

使用官方 `glab` 和原生 Git，支持发现授权仓库、绑定、状态、分支、选择文件提交、快进拉取、本地合并与推送绑定远端。不承诺自动创建远端仓库、MR 或 CI。破坏性重置、强推及企业权限不能由连接自动授权。

## 排查顺序

区分依赖/网络代理、登录/权限、资源/绑定、SSH、提交、平台初始化、训练和回收。原始凭据及完整异常不直接展示普通页面，保留安全分类。不要用删除数据库、清零次数、换账号或重投未知任务解决连接问题。

服务停止时不能监控/唤醒，云任务可继续；复用原数据目录重启后核对原身份。最新小型LPAI单轮、连续闭环也尚未通过；实际范围见[核心交接](core-handover.md)，接口存在不表示所有平台环境均可用。
## 简化实验工作包

已审核、自动创建的单节点组件可以调用 `lpai_prepare.work_package`，只声明实际 Python 入口、参数、输入文件和必要结果：

```json
{
  "entrypoint": "implementation/train.py",
  "args": ["--config", "config/run.json"],
  "files": ["implementation/train.py", "config/run.json", "data.csv"],
  "required_files": ["metrics.json", "split_indices.json"]
}
```

此模式不填写 `patch_file`、`output_contract`、`task_information`。程序从现有方案、实验、正式授权和已审核组件预览生成双入口补丁、绝对目录、结果卷来源及平台时长；不会猜账号、队列、镜像或挂载。必要结果仍由真实训练写入 `ITERLAB_OUTPUT_DIR`，输入位于 `ITERLAB_INPUT_DIR`。平台预计分钟数由原时限换算，不新增运行预算。

**已有原生线程的兼容方式**：工具定义可能已固定，不能仅靠重启服务宣称新参数生效。[官方 App Server 文档](https://developers.openai.com/codex/app-server/)说明动态工具随线程元数据持久化；本机EPT导出的`ThreadResumeParams`不含`dynamicTools`，因此已有线程保持原接口。Executor将上述逻辑声明加上`"schema":"iterlab-experiment/v1"`保存为项目JSON，再用原`lpai_prepare.patch_file`引用它。旧接口要求的任务说明可继续传入，但程序从真实原方案和时限生成平台元信息；不混用`output_contract`。普通补丁数组不按逻辑声明解释。兼容说明按版本绑定到实际原生轮次输入，保留原线程与工具定义，不能替代研究授权。

所有文件按实际字节冻结，数据和已审核原件必须匹配原方案摘要；只在原许可目录内允许追加实现代码。创建组件前完成路径、文件大小、原授权位置、结果清单和实际编码命令长度检查。小型内联工作包沿用最多8文件、单文件64KiB、总量256KiB边界；大数据使用已核验挂载。程序生成的补丁和清单保存在项目 `research/work-packages/`，不能覆盖历史清单。

目前简化模式承载单节点 Python 入口，不自动适配多节点分布式启动或任意镜像初始化命令。多节点、复用已有组件和其他高级场景保留原工作包方式；不把接口可用称为这些场景已通过实网验收。两种方式都经过原方案授权、组件核对、未知写入恢复、提交幂等和结果身份校验。

暂停后由用户明确点击继续或发起恢复操作，可使用同会话 `resume-research` 控制接口：须带稳定 `request_id`、`reason` 和 `confirmed=true`。它只恢复已有未收束方案，不新批方案、不增加额度、不重放未知请求；恢复消息由宿主生成并记录为控制事件，不能伪装成人类研究内容。结果生成后的自动接续仍由原后台机制负责。

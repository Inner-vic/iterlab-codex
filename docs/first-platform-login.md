# 新电脑首次连接公司平台

安装、启用、认证和实际可用性分别判断。浏览器的公司域账号登录，不会自动变成CLI或SDK凭据；交付源码不携带原开发者的凭据。

打开左下角设置，已启用的平台自动检查并复用本机认证；只刷新缺失或过期的检查，不重复填写已经验证的登录。点击首次连接或登录会先做一次实际只读检查，再只为缺少认证的适配器显示配置入口。网络、证书或权限错误单独提示，不要求用户反复更换Token。Windows在确实需要认证时才打开用户主动发起的本机窗口：

| 入口 | 本机窗口做什么 | 官方存储 |
| --- | --- | --- |
| LPAI Agent | 打开官方Agent页，由本人获取Token，隐藏输入；保留原配置其他字段，原子更新api_key | 用户自己的`.config/lpai-agent/config` |
| 训练SDK | 打开LPAI，由本人在个人中心获取训练Token；调用官方LpaiConf保存，不接受Agent Token代替 | 官方SDK自己的配置 |
| GitLab | 执行官方glab网页登录，用户本人完成公司登录和授权 | glab自己的凭据系统 |

密码和Token不经过IterLab HTTP接口、不进入SQLite/事件/研究文件或模型上下文，不通过命令参数传递。HTTP登录入口只接受平台类型，不能接受Token或任意命令。界面只显示工具是否存在、登录窗口是否仍在运行；这些不能冒充认证已通过。

配置成功后本机窗口自动关闭，设置页自动验证并更新状态，无需手动点击检测或编辑配置文件。设置页保持打开时只轮询本机登录窗口状态；关闭设置停止该轮询，再次打开时刷新过期认证。LPAI Agent与训练SDK分别验证，仅缺项引导；GitLab账号读取与Git传输分别验证。SDK Token缺失时，不能把Agent查询成功当成训练接入完成。用户仍可主动重新检测。

缺工具时先安装。Python、Codex/EPT、LPAI工具使用现有依赖安装流程；GitLab官方CLI（glab）需另行安装，再重启服务。运行中的研究、在途或未知云任务未核对前，登录入口阻止更换账号，以免改变后续读取和提交的身份。登录不会启动、停止或重投训练。

如果服务进程由`LPAI_API_KEY`或`LPAI_TOKEN`环境变量指定身份，不能用另一Token悄悄覆盖；需本人更新服务电脑环境并重启。Linux等无本机Windows窗口的环境显示本地交互命令，由部署者执行，不尝试无人值守获取账号凭据。

工程回归覆盖凭据文件保留、环境覆盖阻断、SDK官方配置调用、HTTP拒收凭据、登录窗口去重和活动研究保护。不同同事的真实SSO、Token权限和网络仍需本人在该电脑完成检测；这些不由开发者账号的成功结果代替。
